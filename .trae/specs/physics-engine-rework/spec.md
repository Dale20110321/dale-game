# 物理引擎重做 Spec（第 3 期）

## Why

第 1 期把内容做到了 72 关 + 最终任务，第 2 期把界面做成了成套的视觉体系。但**物理内核仍是原型级实现**，第 1、2 期都在 spec 里把它明确划出范围（"物理引擎手感打磨留给第 3 期"）。当前 [bike.js](file:///c:/Users/1/Documents/GitHub/dale-game/src/physics/bike.js) 的问题不是"参数不够好调"，而是**模型本身不成立**：

1. **注释与实现不符（模型是假的）**：文件头注释宣称"陡坡打滑 / 前轮离地 —— 法向力变小则摩擦上限变小"、"车体 = 三质点刚体，力全部作用在真实位置"，但实现里：
   - 没有任何"法向力 → 摩擦上限"的计算。`TRACTION` 只在刹车与发动机制动两处被当成一个乘数用，**打滑根本没有被模拟**。
   - 求解器是 Verlet + 位置投影（6 次固定迭代），**没有任何质量加权**：三个质点被等量推动，而 [constants.js](file:///c:/Users/1/Documents/GitHub/dale-game/src/config/constants.js#L90-L99) 里定义的 `M_R / M_F / M_H / M_TOT / COM_UP / I_BODY` **全部是死代码，无一处使用**。
   - 驱动力是两个写死的系数（`*1.05` / `*0.95`）加一个大小相同的角冲量，而不是"作用在接地点 → 对质心产生力矩"的推导结果。
2. **地面接触是双向的，所以必须靠猜测开脱**：贴地时两个轮子被锚定在 `groundInfo(x).y - WHEEL_R`，既不能穿入**也不能离开**。于是"坡顶腾空"只能靠启发式补丁实现——用曲率判据 `v²κ > GRAV×LAUNCH_K` 猜"该起飞了"，再把上冲速度**人为截断**到 `LAUNCH_MAX`（[bike.js#L280-L289](file:///c:/Users/1/Documents/GitHub/dale-game/src/physics/bike.js#L280-L289)）。真实的单侧接触约束会自然产生起飞，不需要猜，也不需要截断。
3. **速度是硬夹断的**：`MAXV` 与 `MAXV × DOWNHILL_K` 通过直接改写 `px` **钳死车速**（[bike.js#L486-L505](file:///c:/Users/1/Documents/GitHub/dale-game/src/physics/bike.js#L486-L505)），竖向速度也被 `VSPD_CAP` 夹断。空气阻力与滚阻没有被模拟，下坡不该"加速到某个数就停住"。
4. **悬挂是装饰**：`susClimb` / `susAbsorb` 是位置/速度的钳制系数，`b.squash` 是一个与真实悬挂行程**完全解耦**的独立弹簧，只用来做画面下沉。所以"减震升级"改了之后，车的手感变化是假象。
5. **车轮不转（动力学意义上）**：`wheelRear / wheelFront` 只是按 `v/R` 递增的**视觉角度**。轮子没有转动惯量，因此没有真正的"打滑空转"、没有刹车锁死、没有"油门 → 轮上扭矩 → 摩擦推动整车"这条链条。
6. **补丁遮蔽了不稳定**：`enforceHeadSide()` 把骑手沿轮轴镜像回来，用于掩盖"位置求解器把骑手甩到轮轴下方"的缺陷；`AIR_HEAD_DAMP` 之类的系数是为绕过守恒问题而存在的。
7. **缺少物理正确性护栏**：没有"静止不下滑/不增能"、没有"穿透不超过容差"、没有"求解收敛"、没有"能量不异常增长"这类断言。测试只验了"能通关""帧率无关""落地分级单调"，这些**弱断言在错误模型上同样能通过**。

用户对本期只有一句要求：**"物理引擎你一定要做好"**。因此本期不做参数微调，而是**把刚体动力学模型换成物理正确的版本**，并用能量守恒、穿透、收敛、确定性等强断言把它锁住。

> **范围**：只做物理内核与随之而来的手感。不改玩法数值（关卡数据、机制常量、存档），不做视觉重构（第 2 期已交付）。
> **必须保持**：72 关在"刹车策略"参考骑手下仍全部可通关；后 1/3 关仍无法被全油门通关（第 1 期反向断言）；帧率无关性；标度纪律（所有 px↔m / px/s 换算只允许写在 `constants.js`）；无 `theme === <数字>` 硬编码；零依赖零构建。

## What Changes

### A. 刚体与质量模型（把死代码变成真模型）

- 引入**带质量与转动惯量的刚体描述**：后轮 / 前轮 / 骑手三质点的质量来自车辆数据（不同车不再只是"倍率"，而是**质量与惯量真的不同**），质心位置与转动惯量由 [constants.js](file:///c:/Users/1/Documents/GitHub/dale-game/src/config/constants.js) 的既有几何推导（复用 `COM_UP` / `I_BODY`，使其不再是死代码）。
- 求解器改为**质量加权的约束求解**（顺序冲量或 XPBD 风格的位置+速度双层修正）：约束修正量按逆质量分配，而不是等量推动三点。
- 迭代次数不再是一个写死的 6，而是**由收敛判据驱动**（达到残差阈值或迭代上限即停），保证"收敛"这件事可被断言。

### B. 单侧接触约束（让起飞成为物理结果，而非猜测）

- 地面接触改为**单侧（unilateral）约束**：接触只能推、不能拉。车轮能承压、不能"粘"在地面上。
- 随之**删除** `LAUNCH_K` 启发式起飞判据与"把上冲速度截断到 `LAUNCH_MAX`"的实现；也删除 `rearAir` / `frontAir` 这套"腾空中"的状态机补丁（应由约束活跃/非活跃自然表达）。
- 接触点使用地形的**解析法线**（由地形数据求导得到），不再只用竖直方向。

### C. 轮上动力学（油门 → 扭矩 → 摩擦 → 整车）

- 两个车轮各自带**转动惯量与角速度**；`wheelRear / wheelFront` 从"视觉角度"升级为**真实状态量**，渲染层读取它（视觉仍可加缩放，但来源是物理量）。
- 动力链：油门产生**轮上扭矩** → 通过轮胎与地面的**摩擦上限**转成地面切向力 → 推动整车；超出摩擦上限的部分表现为**空转打滑**（轮速明显高于车速）。
- 刹车产生反向扭矩；扭矩过大时**锁死**（轮角速度归零、切向转为滑动摩擦）。
- 摩擦上限由**法向接触力 × 摩擦系数**决定（摩擦系数来自场景 `THEMES[i].traction` 与车辆 `grp`、轮胎升级）。这是"陡坡打滑 / 前轮离地"能被真正模拟的关键，也把文件头那句注释**变成事实**。

### D. 悬挂：真实的弹簧-阻尼 + 行程限位

- 每个车轮一条**弹簧-阻尼悬挂**（刚度 / 阻尼 / 行程上限来自车辆与减震升级），轮子相对车架有真实位移。
- 画面下沉（`squash`）改为**由悬挂行程与压缩速度驱动**的派生视觉量，不再是一个独立弹簧；因此"减震升级"会真实改变抓地与落地表现。
- 落地冲击、连续颠簸、陡坡贴地能力全部由同一套悬挂产生，而不是散落的特判。

### E. 阻力与极速：删掉硬夹断

- 加入**空气阻力**（与速度平方相关）与**滚动阻力**（与法向力相关）。极速成为"驱动力与阻力平衡"的自然结果，**删除** `MAXV` / `DOWNHILL_K` 对车速的直接钳制，以及 `VSPD_CAP` 对竖向速度的钳制（改为仅在数值异常时兜底，并由断言守护其永不触发）。
- 下坡因此可以**自然超过平路极速**（第 1 期已有"下坡超速"断言，本期改为验证"无上限钳制下仍收敛"），同时保证不发散。

### F. 空中姿态：守恒 + 玩家输入的角冲量

- 空中转体改为**角动量守恒**：玩家按键施加**角冲量**（受各车转动惯量影响，惯量大者转得慢），松键后角速度**保持**（不人为衰减）。
- 删除 `AIR_HEAD_DAMP`、`enforceHeadSide()` 镜像补丁等为绕过守恒问题而存在的机制；若求解器仍需要数值保护，必须换成**有物理含义**的手段（如关节约束 + 阻尼耗散），并说明其能量去向。

### G. 地形-物理接口（解析化）

- 地形暴露**解析接口**：`groundY(x)`、坡度、法线、曲率；渲染与物理共用同一套采样（[terrain.js](file:///c:/Users/1/Documents/GitHub/dale-game/src/physics/terrain.js)）；无限模式与关卡模式一致。
- 断层（`STEP_W`）与陡坡处的接触求解必须稳定：不允许爆冲、不允许穿过、不允许卡死（由断言守护）。

### H. 调参与标度纪律

- **全部物理常量集中在 [constants.js](file:///c:/Users/1/Documents/GitHub/dale-game/src/config/constants.js)**：质量、惯量、悬挂刚度/阻尼/行程、摩擦系数映射、空气阻力系数、滚阻系数、扭矩曲线。
- 车辆与升级的差异**通过数据表达**（质量、惯量、抓地、悬挂），不再靠散落的倍率乘算。
- **标度纪律不变**：`px ↔ m`、`px/s ↔ km/h`、半标度 ↔ 真实速度的换算**只允许**写在 `constants.js`；其它文件禁止裸写 `*SUB` / `/SUB`（`*SUBV` 合法）。
- 分层纪律不变：物理层**不得** import `render/` 或 `ui/`（当前 [bike.js](file:///c:/Users/1/Documents/GitHub/dale-game/src/physics/bike.js) 已经 import 了 `render/particles.js`、`render/camera.js`、`core/toast.js`、`core/audio.js` 来播特效与提示——本期把这些**改为通过注入/事件回调解耦**，恢复单向分层）。

### I. 手感目标（可测的验收面）

重做后必须同时满足（全部由自动断言或可复现的固定输入场景验证）：

- **可预测**：同一输入序列 + 同一初始状态 → 完全可复现（逐帧比特级一致）。
- **帧率无关**：1/60、1/120、1/144 下同帧数位移、燃料、计时一致（沿用第 1 期断言）。
- **不打滑处不打滑**：高抓地场景满油门直线加速时，轮速与车速差（滑移率）在阈值内。
- **该打滑处打滑**：冰川/沼泽等低抓地场景或陡坡上，同样油门出现明显滑移率，且加速度显著低于高抓地场景。
- **该起跳处起跳**：过坡顶时自然离地（无启发式判据），且腾空时间与坡形/车速的关系单调合理。
- **不该起跳处不起跳**：缓坡与小起伏上不出现无理由弹跳。
- **翘头与栽头是算出来的**：油门翘头、刹车栽头随扭矩与质心位置变化；重车更难翘头。
- **落地分级依旧单调**：落地下沉/震屏随冲击单调（沿用第 1 期断言）。
- **空翻可达**：滞空 0.9s 内按住方向键可完成 ≥1 圈；惯量大的车转得更慢（可由断言比较）。
- **静止稳定**：在任意坡度（不含超过"静摩擦极限"的极端陡坡）上静止放置不出溜、不抖动、不增能。
- **无穿透**：车轮与地面、障碍物的穿透深度始终 ≤ 容差。
- **无卡死**：任意关卡任意位置从静止都能起步（沿用"安全点"机制但不再依赖它兜底）。
- **不振荡**：悬挂在颠簸路面不出现发散振荡（有阻尼、能量单调衰减）。

### J. 兼容与回归

- 障碍物碰撞、危险段判定、限时门、摔车惩罚的**规则与参数不因物理重做而改变**；但因速度曲线变化，**必须重新标定参考骑手**并跑通 72 关回归。
- 第 1 期的**反向断言**（后 1/3 关全油门不可通关）必须重新成立；若因物理更真实导致"全油门意外能过"或"策略骑手过不去"，必须**调整机制密度或参考骑手策略（而非放宽物理）**并在 spec 中记录结论。
- 三星时限 `den3`、油耗模型与油罐数量推导依赖"参考均速"，物理重做后**必须重新校验**这些依赖（`fuel.js` 与 `world.js` 的注释明确写了"改这里必须同步改那里"）。
- `M_R / M_F / M_H / M_TOT / COM_UP / I_BODY` 及文件头注释**必须与实现一致**：要么被真实使用，要么删除。

## ADDED Requirements

### Requirement: 质量与惯量必须参与求解
物理 **SHALL** 以带质量与转动惯量的刚体模型求解；约束修正 **SHALL** 按逆质量加权分配，**MUST NOT** 对全部质点施加等量修正。车辆数据 **SHALL** 提供质量与转动惯量，且其差异 **SHALL** 可被观测（重车更难被推动/更难翘头）。

#### Scenario: 质量影响加速度
- **WHEN** 在完全相同的地形与输入下分别驾驶最轻与最重的车辆
- **THEN** 结果在物理结果上不同（如角速度为不同值），并且常量 `M_R / M_F / M_H / M_TOT / COM_UP / I_BODY` 全部被真实引用（不再是死代码）

#### Scenario: 逆质量分配
- **WHEN** 对三质点施加同一约束
- **THEN** 各质点的修正量与逆质量成正比，而非等量

### Requirement: 单侧地面接触
地面接触 **SHALL** 为单侧约束（只推不拉）。系统 **MUST NOT** 依赖曲率启发式判据或速度截断来制造腾空；也 **MUST NOT** 依赖"腾空中"这类人工状态机表达能力。

#### Scenario: 坡顶自然腾空
- **WHEN** 以足够速度越过凸形坡顶
- **THEN** 车轮自然离地进入弹道飞行，无需任何启发式起飞判据；且腾空时长随车速与坡顶曲率单调变化

#### Scenario: 缓坡不起跳
- **WHEN** 以相同车速通过平缓起伏
- **THEN** 不出现离地（接触约束保持活跃）

#### Scenario: 无截断痕迹
- **WHEN** 静态扫描物理层源码
- **THEN** 不存在 `LAUNCH_K` / `LAUNCH_MAX` / `VSPD_CAP` / `DOWNHILL_K` 等补丁常量及其使用

### Requirement: 轮上动力学（扭矩—摩擦—空转—锁死）
车轮 **SHALL** 具有转动惯量与角速度状态，并受**轮上扭矩**驱动。轮胎切向力 **SHALL** 受"法向接触力 × 摩擦系数"限制；超出上限的扭矩 **SHALL** 表现为空转（轮速 > 车速）；刹车扭矩过大 **SHALL** 表现为锁死（轮角速度归零、转为滑动摩擦）。

#### Scenario: 高抓地场景不打滑
- **WHEN** 在高抓地场景满油门直线加速
- **THEN** 滑移率（轮速与车速的相对差）保持在阈值内

#### Scenario: 低抓地场景明显打滑
- **WHEN** 在冰川或沼泽场景以同样油门加速
- **THEN** 出现显著滑移率，且加速度明显低于高抓地场景

#### Scenario: 陡坡上法向力下降导致打滑
- **WHEN** 车辆在陡坡上前轮离地、后轮法向力下降
- **THEN** 摩擦上限随之下降，出现打滑，无法继续加速（注释所述行为成为事实）

### Requirement: 弹簧-阻尼悬挂与行程
每个车轮 **SHALL** 具备弹簧-阻尼悬挂与行程上限；画面下沉量 **SHALL** 由悬挂行程与压缩速度派生。减震升级 **SHALL** 改变悬挂行为并因此改变抓地与落地表现。

#### Scenario: 落地分级
- **WHEN** 以不同竖向速度落地
- **THEN** 悬挂压缩量与震屏随冲击单调递增（沿用既有断言，且压缩量来自真实行程）

#### Scenario: 颠簸不振荡
- **WHEN** 高速通过连续颠簸路面
- **THEN** 悬挂不出现发散振荡，振动能量随时间衰减

#### Scenario: 减震升级有效
- **WHEN** 对比减震 0 级与满级在同一落差下的落地

## REMOVED Requirements

### Requirement: 启发式腾空判据
**Reason**：曲率判据 + 上冲速度截断是为掩盖"双向地面约束导致车被粘在地上"的补丁；单侧接触约束下该行为自然产生。
**Migration**：删除 `LAUNCH_K` / `LAUNCH_MAX` 与 `rearAir` / `frontAir` 状态机；腾空由接触约束的非活跃自然表达，测试改为断言"腾空时长随车速与坡顶曲率单调"。

### Requirement: 硬速度夹断
**Reason**：直接改写速度以限制极速/竖向速度，破坏了动量与能量守恒，使下坡超速与腾空表现失真。
**Migration**：以空气阻力与滚动阻力替代；保留仅用于数值异常兜底的上限并由断言守护"永不触发"。

### Requirement: 破坏守恒的姿态补丁
**Reason**：`AIR_HEAD_DAMP`（空中人造阻尼）与 `enforceHeadSide()`（沿轮轴镜像）会引入/消除角动量，掩盖求解器缺陷。
**Migration**：改用守恒的角冲量模型 + 有物理含义的关节约束；若仍需数值保护，必须说明其耗散去向并被能量断言覆盖。
