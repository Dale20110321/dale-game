# 进度阶梯 · 内容扩容 · 机制性难度 重构 Spec（第 1 期）

## Why

现在这个游戏"十分钟就玩完了"，两个原因：

1. **内容太少**：全游戏只有 20 关、4 个场景（绿野/雪原/荒漠/月面），一条线性列表通关即结束，没有长期目标。场景也少得可怜——4 个主题看两遍就腻了。
2. **难度是假的**：自动化测试证明**全油门 + 空中修正就能 20/20 全部通关**（见 `tools/autotest.mjs` 的 20 关自动试跑）。所谓"难度递增"只是把坡调陡，玩家不需要学任何东西，按住 `→` 就能通关。

本期把游戏从"20 关的演示"变成"能玩很久的完整游戏"：**场景扩到 12 个、关卡扩到 72 关 + 最终任务**，叠加**能长期追求的进度阶梯**（支线 → 最终任务 → 排位赛 → 登顶 → 无限模式自由选图），并引入**机制性约束**让"一直按油门"在后期物理上不可行。

> 范围经与用户确认：分三期交付。**第 1 期 = 内容扩容 + 进度阶梯 + 机制性难度**；第 2 期 = UI 重构（暗色玻璃拟态 + 霓虹渐变）；第 3 期 = 物理引擎手感打磨。本期不做视觉重构，新面板沿用现有 CSS 语言，只求"结构清晰、能玩"。

## What Changes

### A. 场景扩容：4 → 12 个（并做数据驱动重构）

现在 `render/background.js` 与 `render/terrain.js` 里对主题是**硬编码分支**（`store.phys.theme === 3`、`th === 1 ? ... : th === 2 ? ...`），`entities.js` 的装饰也是按 `kind` 字符串硬编码。这种写法每加一个场景都要改渲染代码，扩不到 12 个。

因此先把场景系统**改为数据驱动**，再扩容到 12 个场景。每个场景是一份完整数据：名称、重力、抓地、天空渐变、太阳、地表配色、地表纹理类型、装饰物组合、背景图层描述、环境特效（雪/沙/星/灰烬/雨）。

12 个场景：绿野、雪原、荒漠、月面、雨林、火山、冰川、红岩峡谷、沼泽、城市废墟、天空浮岛、极夜星空。

### B. 关卡扩容：20 → 72 关 + 最终任务

- **12 条支线 × 每条 6 关 = 72 关**，每条支线对应一个场景（支线即"场景章节"）。
- 新增 **1 关「最终任务」**：超长赛道，**依次穿越多个场景**（重力/抓地/渲染在赛程中切换），作为全游戏的终局考验。
- 支线内关卡链式解锁；支线之间相互独立、可并行推进。
- 关卡参数（长度、坡度、金币、油耗倍率、机制密度）随**全局进度**单调递增。

### C. 穿插"好玩的"——关卡变体

72 关如果全是常规关也会腻。因此定义 **6 种关卡变体**，按固定节奏穿插（每条支线的第 3、5 关为特殊关，让"常规 → 特殊 → 常规"形成呼吸感）：

| 变体 | 玩法 |
|---|---|
| `normal` | 常规关：金币 + 油罐 + 适量机制 |
| `sprint` | 限时冲刺：门时限极严、无油罐，纯速度考验 |
| `gauntlet` | 障碍迷宫：障碍密集布成通道，必须精准跳跃/绕行 |
| `airtime` | 空翻挑战：目标改成"累计滞空 + 空翻连招达标"而非冲线 |
| `fuelrun` | 燃料极限：全场仅 1 个油罐，必须规划路线 |
| `downhill` | 极速下坡：危险段密集，全速必摔，考验刹车时机 |

### D. 机制性难度（核心：让"全油门"不可行）

四种机制共同构成"必须刹车、必须观察、必须取舍"的玩法：

1. **障碍物**：地形上的岩石/木桩，车身质点碰到即摔车，必须跳过或减速绕行。
2. **危险段**：标记区间，进入时车速超阈值即摔车（"急弯/断崖全速必摔"），强制提前刹车。
3. **限时门**：每关 3~5 道门，累计时限超时本局判负。杜绝"慢慢磨"，与危险段形成"该快时快、该慢时慢"的张力。
4. **摔车惩罚**：摔车不再是"回安全点就没事"——额外扣 8% 燃料 + 2 秒计时惩罚。

### E. 进度阶梯（状态机）

```
主菜单
 └─ 支线任务（12 条 × 6 关 = 72 关，链式解锁，可并行推进）
     └─ 72 关全部通关 ──▶ 解锁「最终任务」（多场景串联）
         └─ 最终任务通关 ──▶ 收到「比赛邀请」──▶ 解锁「排位赛」
             └─ 排位赛胜负累计段位分 rating
                 ├─ rating ≥ 1200 ──▶ 解锁「高级排位赛」（AI 显著更强）
                 └─ rating ≥ 2400（顶峰）──▶ 解锁「无限模式 · 自由选图」
                     └─ 无限模式：自选 12 个场景中已通关的任意场景探索
```

### F. 浏览器本地存档（把已有的存档做成"看得见、管得住"）

游戏**已经**在用浏览器 `localStorage` 存 `bike_*` 键（金币/升级/解锁/星级/车辆/成就/静音/纪录），只是既没有说明、也没有管理入口。本期把它补成一个完整、可见、可管理的存档系统：

- **持久化范围明确化**：金币、每辆车升级、关卡解锁、72 关星级、车辆拥有与当前车、成就、静音、无限模式纪录，**加上本期新增**的进度阶梯（支线完成/最终任务/排位邀请/段位分/战绩/登顶）、已解锁场景、累计统计（总局数 / 总里程 / 总时长 / 最后游玩时间）。
- **新增存档键**（既有 10 个键名一个都不动、不改名）：
  - `bike_prog`：进度阶梯 JSON
  - `bike_rating`：段位分
  - `bike_stat`：累计统计 JSON
- **自动保存时机**：通关结算、解锁新关卡/场景、购买车辆、升级部件、达成成就、段位分变化时**立即写盘**；骑行中每 30 秒兜底写盘一次；切到后台（`visibilitychange`）时写盘。
- **存档管理面板**：显示进度概览（已通关数 / 总星数 / 段位 / 成就数 / 金币 / 累计里程 / 累计时长 / 最后游玩时间），并提供导出、导入、重置三项操作（详见 G）。
- **容错与降级**：任一键缺失或 JSON 损坏 → 该键回退默认值继续，**不得崩溃**；`localStorage` 完全不可用（隐私模式 / 配额满 / 被禁用）→ 首屏提示"本次无法保存进度"，游戏仍可正常游玩。
- **老存档迁移**：旧 `bike_stars`（长度 20）与 `bike_unlocked` 按"旧第 i 关 → 新第 i 关（全局索引）"映射到 72 关结构；72 关的星级数组按需补齐 0。玩家**不丢进度、不回退**。迁移只执行一次，由既有 `bike_v` 版本号机制守护。

### G. 存档导入 / 导出（可备份、可换设备）

`localStorage` 存在浏览器里，换浏览器、换设备、清缓存就没了。因此**必须**提供导入/导出：

- **导出**：一键把全部 `bike_*` 键打包为单个 JSON 文件下载。文件名带时间戳，例如 `dale-bike-save-20260925-1430.json`。
- **文件格式**（自带元信息，便于识别与后续兼容）：
  ```json
  {
    "app": "dale-bike",
    "format": 1,
    "savedAt": "2026-09-25T14:30:00.000Z",
    "data": { "bike_gold": "123456", "bike_stars": "[...]", "bike_prog": "{...}", "...": "..." }
  }
  ```
  `data` 内部刻意保持"原样字符串键值"，与 `localStorage` 一一对应，导入即原样写回，避免字段级解析出错。
- **导入**：选择 JSON 文件 → 校验 `app` / `format` / `data` 结构 → 弹出对比（当前进度 vs 导入进度：通关数、总星数、段位、金币）→ 二次确认 → 原样写回全部键 → 立即重载存档并刷新界面。
- **校验与拒绝**：非本游戏文件、`format` 不支持、`data` 非对象 → 拒绝导入并提示原因，**现有存档保持不变**（先校验后写入，不做半途写入）。
- **导入即覆盖**：导入是"整体恢复"语义，不做字段级合并（合并容易产生自相矛盾的进度）。因此二次确认里必须明确写出"将覆盖当前进度"。
- **两个入口**：菜单的「存档」面板（主入口），以及首屏检测到存档异常时提示可导入备份。

### H. 无变化

- 零依赖、零构建、纯静态文件可直接打开游玩——不变。
- 双键操作、三质点刚体物理模型、燃料模型、升级车间、车库、成就系统——均不改（除摔车惩罚外）。

## MODIFIED Requirements

### Requirement: 场景（主题）系统
场景 **SHALL** 由数据描述，渲染层 **MUST NOT** 出现对具体场景索引/名称的硬编码分支（如 `theme === 3`）。系统 **SHALL** 提供 12 个场景，每个场景至少定义：名称、重力、抓地、天空渐变、太阳色、地表三色、地表纹理类型、装饰物组合、背景图层描述、环境粒子类型。

#### Scenario: 全部 12 个场景可渲染
- **WHEN** 依次把 `store.phys.theme` 设为 0~11 并绘制一帧
- **THEN** 每个场景都成功渲染且无异常；渲染层源码中不存在 `theme === <数字>` 形式的硬编码分支

#### Scenario: 场景物理生效
- **WHEN** 在重力 350（月面/天空浮岛）与重力 750（绿野）的场景各跑一段相同输入的物理模拟
- **THEN** 两者的落地/腾空行为不同，且与各自场景数据中声明的重力一致

### Requirement: 关卡推进与解锁
关卡 **SHALL** 以"支线任务"为单位组织：12 条支线、每条 6 关，对应 12 个场景；支线内关卡**链式解锁**（通过第 N 关才解锁第 N+1 关），支线之间相互独立可并行推进。72 关全部通关 **SHALL** 解锁最终任务。

#### Scenario: 支线内链式解锁
- **WHEN** 玩家在"雨林"支线通关其第 2 关
- **THEN** 该支线第 3 关解锁，第 4~6 关仍锁定；其它支线进度不受影响

#### Scenario: 全部支线完成解锁最终任务
- **WHEN** 12 条支线共 72 关全部通关
- **THEN** 「最终任务」入口在菜单中出现并可进入；此前该入口显示锁定

#### Scenario: 关卡总数
- **WHEN** 统计关卡配置
- **THEN** 恰好 12 条支线、每条 6 关、合计 72 关，另有 1 关最终任务

### Requirement: 难度递进
难度 **SHALL** 由"机制密度"而不仅是坡度驱动：障碍物数量、危险段数量、限时门严格度 **MUST** 随全局关卡进度单调递增。前 1/3 关卡为教学难度（保留全油门可通关的余量），后 1/3 **MUST** 使得"全程不刹车"无法通关。

#### Scenario: 后期关卡拒绝全油门
- **WHEN** 用"全程按住加速 + 仅空中姿态修正"的自动骑手试跑每一关
- **THEN** 至少后 1/3 的关卡**无法通关**（触发障碍碰撞摔车、危险段超速摔车或限时门超时），且失败原因可被区分统计

## ADDED Requirements

### Requirement: 关卡变体
关卡 **SHALL** 支持 6 种变体：`normal` / `sprint` / `gauntlet` / `airtime` / `fuelrun` / `downhill`。每条支线的第 3 关与第 5 关 **SHALL** 为特殊变体（非 `normal`），其余为常规关。变体 **SHALL** 在关卡数据中显式声明，并影响该关的实体生成与结算条件。

#### Scenario: 变体穿插排布
- **WHEN** 遍历 12 条支线的关卡变体字段
- **THEN** 每条支线的第 3、5 关变体均不为 `normal`，且 6 种变体在全游戏中都至少出现一次

#### Scenario: 空翻挑战关的结算条件
- **WHEN** 玩家在 `airtime` 变体关到达终点但累计滞空/连招未达标
- **THEN** 本关不判通过（提示还差多少），达标后才正常结算

#### Scenario: 燃料极限关
- **WHEN** 进入 `fuelrun` 变体关
- **THEN** 全场油罐数量为 1，且该关的可达性经自动试跑验证可通过

### Requirement: 最终任务多场景串联
最终任务 **SHALL** 为一条超长赛道，赛程中 **SHALL** 按分段切换场景（重力、抓地、渲染主题随之改变）。分段切换 **MUST NOT** 造成物理不连续（不允许因切换重力导致车身瞬移或速度异常）。

#### Scenario: 赛程中穿越多个场景
- **WHEN** 玩家在最终任务中骑行跨越场景分界点
- **THEN** 该位置之后的渲染主题与物理环境切换为新场景，车身位置与速度连续、无跳变

### Requirement: 障碍物碰撞
车身三个质点与障碍物 **SHALL** 做碰撞检测；命中即判定摔车，并触发与撞地一致的摔车流程。

#### Scenario: 撞上岩石
- **WHEN** 车身任一质点与障碍物圆心距离小于碰撞半径
- **THEN** 本局进入摔车状态，按摔车惩罚处理，并触发撞击粒子与音效

#### Scenario: 跳过障碍
- **WHEN** 玩家借助坡顶腾空使车身整体越过障碍
- **THEN** 不发生碰撞，可以正常通过

### Requirement: 危险段超速判定
危险段 **SHALL** 在关卡数据中标记为区间（起止 x + 速度阈值）；车身中点进入该区间时若 `|bike.speed|` 超过阈值，**SHALL** 判定摔车。危险段 **SHALL** 有可提前预判的视觉提示。

#### Scenario: 全速冲进急弯危险段
- **WHEN** 玩家以高于阈值 20% 的车速进入危险段
- **THEN** 立即摔车并被提示"减速！"；以低于阈值的车速进入则不触发

### Requirement: 限时门
关卡 **SHALL** 含 3~5 道限时门，每道门给出"相对本关起点的累计时限"。通过门的瞬时时间（`store.time - run.levelStartTime`）超过其时限 **SHALL** 判定本局失败。

#### Scenario: 磨蹭超时
- **WHEN** 玩家通过第 2 道门时累计用时超过该门时限
- **THEN** 本局判负：提示超时原因，本局结束并回到该关入口（不计星、不计解锁）

#### Scenario: 按时通过
- **WHEN** 玩家在时限内依次通过全部门并抵达终点
- **THEN** 正常结算星级与解锁

### Requirement: 摔车惩罚
摔车 **SHALL** 除"回到安全点"外，额外扣除 8% 燃料，并为本关计时累加 2 秒惩罚（计入 `elapsed`，影响三星判定）。

#### Scenario: 摔车两次
- **WHEN** 一局中摔车两次
- **THEN** 燃料累计被扣 16%，本关用时被累加 4 秒，三星判定使用累加后的用时

### Requirement: 比赛邀请与排位赛段位
最终任务通关后 **SHALL** 解锁排位赛。排位赛 **SHALL** 以段位分 `rating` 记录成绩：获胜加分、失败扣分（下限 0）。排位赛对手强度 **MUST** 随 `rating` 提升。

#### Scenario: 最终任务通关收到邀请
- **WHEN** 玩家通关最终任务
- **THEN** 弹出"收到比赛邀请"提示，菜单出现「排位赛」入口，`progress.invited = true` 并持久化

#### Scenario: 段位分变化
- **WHEN** 玩家赢得一场排位赛
- **THEN** `rating` 增加并在菜单实时显示；失败时减少但不低于 0

### Requirement: 高级排位赛与顶峰
`rating` 达到 1200 **SHALL** 解锁「高级排位赛」（AI 基准速度与加成显著高于普通排位赛）。`rating` 达到 2400 **SHALL** 视为"达到顶峰"，解锁「无限模式 · 自由选图」。

#### Scenario: 晋升高级赛
- **WHEN** `rating` 由 1190 变为 1210
- **THEN** 「高级排位赛」入口解锁，且其 AI 强度高于普通排位赛（可由自动断言比较）

#### Scenario: 登顶解锁无限选图
- **WHEN** `rating` 达到 2400
- **THEN** 无限模式入口从"随机地形"升级为"可自选场景"，`progress.peak = true`

### Requirement: 无限模式自由选图
达到顶峰后，无限模式 **SHALL** 允许玩家在 12 个场景中已通关的场景里自由选择后进行探索。

#### Scenario: 选择火山场景探索
- **WHEN** 玩家在无限模式选择"火山"场景
- **THEN** 无限模式以火山场景的物理环境（重力/抓地）、地表渲染与环境特效开始生成地形

### Requirement: 进度持久化与存档迁移
全部进度 **SHALL** 持久化在浏览器 `localStorage`（键名前缀 `bike_`）。进度阶梯持久化到 `bike_prog`、段位到 `bike_rating`、累计统计到 `bike_stat`。加载 **SHALL** 将老存档（20 关结构）映射到新的 72 关支线结构，玩家不丢失已有进度。

#### Scenario: 关键节点立即落盘
- **WHEN** 玩家通关一关并解锁新关卡、或赢得一场排位赛使段位分变化
- **THEN** 刷新页面（或关闭后重新打开）时这些变化仍在，无需手动保存

#### Scenario: 老存档迁移
- **WHEN** 存在旧存档（`bike_unlocked = 7`、`bike_stars` 长度 20）而 `bike_prog` 不存在
- **THEN** 迁移后旧第 i 关的星级被保留到新结构的第 i 关（全局索引），"前 8 关已解锁"被保留，且不触发任何进度回退

#### Scenario: 无老存档
- **WHEN** 全新玩家（无任何 `bike_` 键）
- **THEN** 仅第 1 条支线第 1 关解锁，其余锁定，最终任务与排位赛入口不可用

### Requirement: 存档导入 / 导出
系统 **SHALL** 支持把全部存档导出为单个 JSON 文件，并支持从该文件导入恢复。导出文件 **SHALL** 含 `app` / `format` / `savedAt` / `data` 四个字段，其中 `data` 与 `localStorage` 的 `bike_*` 键一一对应。导入 **SHALL** 先完整校验再整体写回，校验失败 **MUST NOT** 修改任何现有存档。

#### Scenario: 导出生成可识别的文件
- **WHEN** 玩家在存档面板点击导出
- **THEN** 浏览器下载一个文件名形如 `dale-bike-save-<时间戳>.json` 的文件，内容含 `app = "dale-bike"`、`format`、`savedAt` 与 `data`（覆盖全部 `bike_` 键）

#### Scenario: 导出后重置再导入，进度完全恢复
- **WHEN** 玩家导出存档 → 重置存档 → 导入刚导出的文件并确认
- **THEN** 关卡星级、已解锁关卡与场景、段位分、金币、成就、车辆与升级全部恢复到导出时的状态

#### Scenario: 导入前展示对比
- **WHEN** 玩家选择了一个合法存档文件
- **THEN** 在写入前弹出"当前进度 vs 导入进度"的对比（通关数、总星数、段位分、金币）并明确提示"将覆盖当前进度"

#### Scenario: 导入非法文件
- **WHEN** 玩家选择一个非本游戏存档（如 `app` 不匹配、`format` 不支持、或 `data` 不是对象）的 JSON 文件
- **THEN** 导入被拒绝并提示失败原因，现有存档**保持不变**（不出现部分键被覆盖的中间状态）

### Requirement: 存档管理面板
系统 **SHALL** 提供存档管理入口，展示进度概览并提供导出、导入、重置三项操作。重置 **SHALL** 经二次确认。

#### Scenario: 进度概览
- **WHEN** 打开存档管理面板
- **THEN** 显示已通关关卡数、总星数、段位分、成就数、金币、累计里程、累计时长与最后游玩时间

#### Scenario: 重置存档
- **WHEN** 玩家点击重置并二次确认
- **THEN** 全部 `bike_` 键被清空，界面回到新玩家初始状态（仅第 1 条支线第 1 关解锁）

### Requirement: 存档容错与降级
加载存档时任一键缺失或内容损坏 **MUST NOT** 导致崩溃；该键 **SHALL** 回退为默认值继续运行。当 `localStorage` 不可用（隐私模式 / 配额满 / 被禁用）时，系统 **SHALL** 提示"本次无法保存进度"，且游戏 **SHALL** 仍可正常游玩。

#### Scenario: 存档损坏
- **WHEN** `bike_stars` 被写入非法内容（如 `"{"`）
- **THEN** 游戏正常启动，该字段按默认值处理，其它字段的进度不受影响

#### Scenario: localStorage 不可用
- **WHEN** `localStorage` 的读写抛出异常
- **THEN** 首屏出现"本次无法保存进度"提示，进入游戏后所有玩法可正常进行，不出现报错中断
