## 怎么玩

| 按键 | 作用 |
|---|---|
| `→` / `D` | 踩油门 |
| `←` / `A` | 刹车 |
| `↓` / `S` | 倒车（先当刹车用，停稳后才挂上倒挡） |
| 空中 `←` / `→` | 调整车身姿态，决定落地是压平还是翻车 |

**没有跳跃键。** 想腾空只能靠冲上坡顶甩出去 —— 所以"什么时候松油门"比"按什么键"重要得多。

移动端直接触屏操作，左下角是虚拟按键。

## 游戏里有什么

**36 个场景 × 12 关 = 432 关**，外加一个最终任务。四种玩法：

| 玩法 | 内容 |
|---|---|
| **闯关** | 432 关主线，通关解锁下一关；三星分别对应"通关 / 吃满 70% 金币 / 跑进限时" |
| **比赛** | 三种赛制：**1V1 竞速**（单挑）、**多人竞技**（6 人同场，按名次发奖）、**团队接力**（3v3，比两队累计里程） |
| **排位赛** | 14 个段位（青铜 → 超越）× 3 星。1200 分开高级赛，3300 分登顶解锁无限模式自由选图，12000 分刷满全表 |
| **无限模式** | 无终点，随里程加难。**每次进入地形和场景都会重新摇** —— 不会每次打开都是同一条路 |

每关的地形都是当场算出来的：先按难度挑一组地貌气质，再撒随机种子决定波长、相位、断层落点，最后实测一遍最大坡度、缩放到目标值。所以**同一关每次重玩的起伏细节都不一样，但难度是稳定的**。

### 26 辆车

**分 5 档**（普通 → 稀有 → 史诗 → 传说 → 神话）。规则很简单：

- **越贵越强**。车价按**实测综合能力**（极速 / 抓地 / 油箱 / 扭矩）排序，不是拍脑袋填的。
  单项不必每台都递增 —— 一台车可以某个地方特别突出、某个地方稍弱；但**综合能力一定随价格递增**。
- **贵的车升级更贵**。四项升满 = 基础 28,240 × 档位倍率（普通 1 → 神话 40）。
- **贵的车形态更贵**，25 个形态的价格从 8,000 一路涨到 1,020,000。
- **最高级的那台车「奇点」什么都是最好的** —— 极速、抓地、油箱、扭矩四项全场第一，
  也是唯一一台能开到 **350 km/h** 的车（要开它的「绝对形态」）。

起步送你一台免费试骑车「驮马」。它是**借来的**，刻意排在价格阶梯之外 ——
第一笔钱该拿去升级它，而不是换车。

除了这台借用车，每辆车都有一个专属形态：贴地锁死、极速过载、摔不坏、燃料无限、轨道炮、持续喷射……
七种形态在物理层各有一段实现。

**钱从哪来**：通关固定奖励 + 赛道上的金币 + 比赛名次奖金 + 排位赛奖金与升段奖励。
一轮 432 关全通约 210 万；刷满一整条段位表另有 56.2 万。前 30 关左右就能把一台入门车升满。

## 本地跑起来

零依赖，**但需要一个静态服务器**（ES module 不能用 `file://` 直接打开）：

```bash
node tools/_serve.mjs      # 然后打开 http://localhost:8765
```

或者用任何你顺手的静态服务器：

```bash
python -m http.server 8765
npx serve .
```

### 想直接看所有车？

浏览器控制台执行这一行，刷新即可解锁全部车辆和 200 万金币：

```js
localStorage.setItem('bike_trial', '1'); location.reload()
```

删掉 `bike_trial` 这个键就恢复正常规则。

## 部署到 GitHub Pages

推上去之后进仓库 `Settings → Pages`，Source 选 `Deploy from a branch`，
分支 `main`、目录 `/ (root)`，保存即可。**不需要任何构建步骤。**

访问地址：https://dale20110321.github.io/dale-game/

> **想用干净的 URL（`/garage` 而不是 `/#garage`）？**
>
> GitHub Pages 是纯静态托管，没有服务端 rewrite，`/garage` 刷新会 404。
> 想做到"刷新后停在原页面"，只能用 **hash 路由**（`index.html#garage`）——
> 哈希不会发给服务器，所以它在 GitHub Pages 上一定可用。
>
> 好消息是游戏状态本来就存在 localStorage 里（当前关卡、当前车辆都存了），
> 所以刷新丢的只是"回到哪个面板"，进度不会丢。真要做的话，
> 加一个 `src/ui/router.js` 导出 `routeTo / currentRoute / startRouter`，
> 由 `main.js` 统一接线，不用动其它文件。

### 想生成一个可以双击游玩的单文件？

```bash
build.bat          # 需要 bun，产出 dist/game.bundle.js
```

日常开发不需要这一步，`index.html` 直接加载 `src/main.js`。

## 想改点什么

```
src/
├── config/          ← 数据都在这，改数值不用碰逻辑
│   ├── constants.js    所有物理常量 + 升级/金币/段位表/赛制的唯一出处
│   ├── vehicles.js     26 辆车的数据
│   ├── levels.js       432 关的生成规则 + 地貌体格
│   └── themes.js       36 套场景主题
├── physics/         物理内核：刚体、接触、悬挂、动力链
├── render/          Canvas 绘制
├── ui/              菜单、车库、升级车间、结算等界面
├── game/            关卡流程、比赛、结算、进度
└── core/            存档、输入、工具
```

**三条最容易踩的规矩：**

1. **物理量只能在 `config/constants.js` 里换算。**
   别处写 `* 6` 这类魔法数，标度一旦分裂，HUD 显示的和实际跑的对不上，排查起来非常痛苦。

2. **`render/` 不许 import `game/`。**
   依赖是单向的：config ← physics ← game ← render/ui。反向 import 会把渲染和游戏逻辑绑死，
   以后想单独复用渲染层就做不到了。确实要共用的纯函数，往 `config/` 放。

3. **加车只要在 `vehicles.js` 里加一条，然后挂一个 `ultra.mode`。**
   七种形态（`stable` / `surge` / `shield` / `phase` / `railgun` / `warp` / `absolut`）
   在物理层各有一段实现，新车**不需要改任何 `if`**。

### 改数值之前先知道这几件事

`vehicles.js` 里有几条看起来莫名其妙的限制（`mass` 必须两两不同、
`air × inertia` 必须等于 1、`grp` 不宜超过 2.2），都是被物理逼出来的，改之前先看那里的注释。

**改地形难度前先读 `levels.js` 的文件头注释。** 坡度不是直接给的，
而是"生成 → 实测 → 反解缩放系数"得到的，绕过这一步直接改振幅会让难度曲线断掉。

**改完 `phys` 要重排车价**，不然就会出现"更贵的车反而更弱"。
同理，**段位名不要和车名重名** —— 玩家分不清「奇点」是段位还是车。
