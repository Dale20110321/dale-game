## 🏔️ 地形生成：形状随机 × 难度受控

地形过去是**全场一套**：72 关共用同一组波长（2600/1000/400）与相位（1.7/3.1/5.2），
只有振幅随难度变大 —— 于是每关看起来都像同一条路。现在改为：

| 层 | 做什么 |
|---|---|
| **地貌体格 mood** | 12 种（起伏丘陵 / 连绵沙丘 / 碎浪连包 / 深谷沟壑 / 连绵山脊 / 阶梯平台 / 断裂天堑 / 嶙峋台地 / 长缓丘陵 / 断崖飞坡 / 泥泞浅滩 / 登峰造极），一条支线一种底色 |
| **每关种子** | `mulberry32(gi)` 决定该关的波长抖动、相位、局部地貌种类与落点、断层位置 |
| **局部地貌** | 起跳唇 kicker / 洼地 dip / 平台 shelf / 碎浪 whoops / 深谷 chasm / **长直坡 ramp** 6 类，按体格权重沿赛道播撒 |
| **fitSlope 标定** | 生成后**实测**最大坡度，反解一个整体缩放系数把地形精确缩放到目标坡度 |

**为什么形状可以随便随机、难度却仍然单调？** 地形高度对所有振幅是**线性**的，
所以坡度也对振幅线性 —— `maxSlope(整体) = k · maxSlope(原始)`，反解 `k` 是闭式的、无需迭代。
于是体格可以彻底自由随机，而 `maxSlope` 仍严格沿全局进度递增（19.5° → 54°，实测误差 0.000°）。

三条踩过的坑，都写在 `src/config/levels.js` 的注释里：

1. **宽度是物理约束，不是审美**。接触带只有 `CONTACT_BAND=2px`，地形曲率决定落地时法线翻转的剧烈程度。
   特征波长压到 340px 以下时曲率超出约束求解器收敛能力（实测车架约束瞬时漂移 20px、高速穿断层 4px）。
   所以宁可"宽而缓"（玩家能预判、能规划），也不要"窄而陡"（解算器直接失稳）—— 变化靠波长配比与地貌组合。
2. **难度上限被断层曲率锁死**。陡度几乎全部来自断层（落差 D 铺在 150px 上 → 坡度 ≈ D/100），
   曲率 ≈ `6·D/STEP_W²`。所以目标坡度上限取 **54°** 而非原曲线的 57.6° ——
   抬到 57.5° 会迫使 `fitSlope` 把断层放大到 167px，曲率随之涨出原包线。
3. **长直坡 = 不抬曲率的难度**。想加难度又不动曲率，用 `ramp`：19° 的长直爬坡，
   中段曲率恒为 0（求解器无感），只在首尾余弦过渡处有微小曲率。

**当前生效的局部地貌只有 `ramp` 一类**（这是实情，不是没做完）：上表 6 类地貌的**形状函数与播撒逻辑全部在位**，
但另外 5 类（`kicker` 起跳唇 / `dip` 洼地 / `shelf` 平台 / `whoops` 碎浪 / `chasm` 深谷）的振幅被
`src/config/levels.js` 里的 `FEAT_AMP_MAX` **标定为 0**，等于不产生地形起伏。
逐档实测的结论写在该常量的注释里：把 `FEAT_AMP_MAX` 抬到 5 / 9 / 12 / 18 会依次让 autotest 变红
（陡坡法向力对比失配 → 低速过坡顶也被弹飞 → "全油门不可通关"反向验收掉到 15/24 → 悬挂压缩对比落在刀刃），
即这 5 类与已标定的三条物理不变式（坡度标定 / 低速不腾空 / 后 1/3 关全油门不可通关）**不兼容**。
要启用必须先重新标定那三项，不能只把振幅调大；`ramp` 是唯一例外（中段曲率恒为 0，不触碰任何一条），
故单独按 `RAMP_GRADE` 计算。深度体检里有一条断言专门防"代码在、功能死"的退化（查真有振幅而非查有字段）。

**累计爬升**是另一条隐形的红线：固定坡度下 `累计爬升 ∝ 1/λ`，
所以三层波动的振幅必须**长波主导**（约 80%/15%/5%），否则末关爬升会从 1084px 涨到 1900px+，
参考骑手 150s 骑不完，限时门与三星时限全部失配。断层间距的抖动也收在 ±18%：
间距一小就会连成串，实测出现 828px 的密集断层群，参考骑手被反复弹起、落地倒立、
摔车重生回到同一处 —— 直接死循环。

验证：72/72 关参考骑手可通关（9~37s）、曲率包线与原曲线一致（+0.037/−0.037 vs 原 +0.039/−0.037）、
爬升 0.74~1.24× 原预算、72 关地形指纹两两不同。

## 🗺️ 内容与玩法

**场景（12）**：绿野、雪原、荒漠、月面、雨林、火山、冰川、红岩峡谷、沼泽、城市废墟、天空浮岛、极夜星空。
每个场景有各自的重力、抓地、天空/地表配色、装饰与环境特效（数据驱动，渲染层无 `theme === 数字` 硬编码）。

**关卡**：12 条支线 × 6 关 = 72 关，另加 1 关「最终任务」（超长赛道、多场景分段串联）。
支线内链式解锁、支线间可并行推进；难度（坡度 / 落差 / 颠簸 / 机制密度 / 三星时限）沿全局进度单调递增。
72 关全通后解锁「最终任务」，通关最终任务 → 收到比赛邀请 → 解锁排位赛。

**关卡变体（6）**：每条支线的第 3、5 关是特殊变体，其余为常规关。

| 变体 | 内容 |
|---|---|
| `normal` | 标准赛道 |
| `sprint` | 限时冲刺：门限极严、赛道无补给 |
| `gauntlet` | 跳台狂飙：跳台密集、断层相连，须攒够滞空 |
| `airtime` | 空翻挑战：需累计滞空 + 连招达标才算通关 |
| `fuelrun` | 燃料极限：赛道仅 1 个油罐，必须规划 |
| `downhill` | 极速下坡：危险段密集，须精准刹车 |

**机制性难度**：

- **燃料**：行驶即耗油，全油门约为滑行的 4 倍；赛道油罐按油耗公式反推，够通关但不宽裕
- **危险段**：车身中点进入且**整车瞬时水平速度**超阈值必摔车，有可提前预判的限速路标。判速用的是 `bikeVx()`（`systemVel` 的质量加权平动速度，旋转项自动抵消、无滞后），不是单点差分——否则车身俯仰/落地压缩时前轮的位移差分会瞬间冲到限速数倍，明明没超速也被判超速
- **跳台**：贴地高速压上去获得向上冲量腾空；空翻 / 跳台变体须累计滞空达标才能通关
- **限时门**：每关 3~5 道，累计时限比三星放宽 20%；任一门超时本局判负，且不写入星级与解锁
- **摔车惩罚**：每次摔车扣 8% 燃料 + 2 秒计时惩罚（计入三星判定用时）。判据是**「车架翻过 tiltMin」且「骑手身体落到地面附近」两条同时成立**：空中倒立不判摔（实测可存活 50+ 帧自由落体，落地接触才判），车架等级同时放宽角度阈值（0 级 ≈99° → 满级 ≈124°）与落地距离阈值（30px → 20px），**擦过垂直线有活路可以用空中转体救回**
- **加速带**：贴地压上获得一次瞬时提速；只铺在"前方迎面是上坡"处，且与危险段保持一次刹车距离（绝不塞进限速区）

**玩法模式**：

- **闯关**：主页面即关卡地图 —— 顶部是最终任务卡，中间直接展开当前支线的 6 个关卡格，下方是 12 条支线总览；当前该打的那条会绿色高亮并标注「▶ 继续 第 N 关」
- **比赛**：与 AI 对手在同一赛道竞速，先到终点者胜（胜 +300 金币）
- **排位赛**：普通 / 高级两档；胜负改变段位分（不低于 0），段位分 ≥ 1200 解锁高级赛，≥ 2400 视为登顶
- **无限模式**：未登顶为随机地形；登顶后可自选已通关场景（重力 / 抓地 / 地表 / 环境特效随之切换）

## 🚀 运行

**直接双击 `index.html` 就能玩**（`file://` 也可以）。

入口是 `<script src="dist/game.bundle.js">` —— **普通 script，不是 ES module，且是唯一入口**。
两点很关键：

1. ES module 在 `file://` 下会被浏览器按 CORS 拦截，`main.js` 根本不执行，
   页面只剩静态 HTML（按钮全哑、关卡地图空白），看起来像"坏了"。
2. 源码入口 `src/main.js` 在 `index.html` 里**只作兜底**（打包文件缺失 / 加载失败时才动态
   `import`）。两个入口若同时执行，整个游戏会被初始化**两遍** —— 两套 store、两条主循环，
   却共用同一个 DOM 和同一份 localStorage，所有交互都触发两次
   （最典型的是存档面板里点一次「✨ 新建存档」会连建两个存档）。

> ⚠️ **改完源码要重新打包**，否则 `dist/game.bundle.js` 还是旧的：
> 双击 `build.bat`（或 `bun build src/main.js --outfile dist/game.bundle.js --target browser --format iife`）。

如果你更想用本地服务器调试（改源码即时生效，不必每次打包）：

```bash
node tools/_serve.mjs         # 端口 8765，带 no-store 免缓存，自动改走源码入口
```

`tools/_serve.mjs` 会在返回 `index.html` 时把打包入口换成源码入口，所以 F5 就是最新代码。
（`python -m http.server` / `npx serve` 不做这个改写，用它们仍需先 `build.bat` 重新打包。）

## 🏁 比赛模式的 AI 配速

AI 巡航速度按**本关三星要求均速 `den3`** 标定（而不是玩家极速 `MAXV`）——因为 `MAXV` 由车辆/升级决定，
不随关卡变难而提高；早期实现用 `MAXV×(1+42%×ramp)` 会让后期 AI 达到三星节奏的 2~3 倍，比赛几乎必输。

| 模式 | AI 配速（相对 `den3`） | 追赶修正 |
|---|---|---|
| 普通比赛 | `0.68×` | 有（`[0.80, 1.25]×`，AI 领先降速 / 落后提速） |
| 普通排位赛 | `0.70× → 0.90×`（随段位分） | 无（纯配速检验） |
| 高级排位赛 | `0.95× → 1.25×`（随段位分） | 无 |

普通比赛的配速上限为 `0.68 × 1.25 = 0.85 × den3 < 1`，因此**只要跑出三星水平就必定赢**；追赶修正保证对手
不会一路绝尘，也不会因一次小失误就被拉开。

## ⚙️ 物理引擎（第 3 期：重做）

物理内核在 `src/physics/bike.js`（约 700 行），**只依赖 `config/constants.js` 与 `physics/terrain.js`**，
不 import `render/`、`ui/`、`toast`、`audio`：物理只派发事件（`physics/events.js`），震屏 / 音效 / 粒子 / 提示在 `game/` 层接线。

| 模块 | 模型 | 说明 |
|---|---|---|
| 刚体 | 车架三质点（后轴 / 前轴 / 骑手）+ 两独立车轮 | 质量 / 质心高度 / 转动惯量由车辆数据推导（`deriveRigidBody`），**换车真的会变重、变难翻、变难停** |
| 约束 | 顺序冲量 + 逆质量加权 + 位置投影 | 收敛判据驱动（残差 < `SOLVER_TOL=0.05px` 即提前退出，上限 `SOLVER_ITERS=10`）；位置投影消除长期漂移，实测车架刚性误差均值 ≈0.013px |
| 接触 | **单侧**（只推不拉）+ 解析法线 | `groundNormal(x)` 直接对 `levelHillY` 求导；接触带 `CONTACT_BAND=2px`，出带即无接触 → **坡顶腾空是"漏掉支撑"的结果，不是起飞脚本** |
| 轮上动力学 | 底轮转动惯量 `½mR²` + 扭矩曲线 + 库仑摩擦 | 滑移率 `slip = v·t − ωR`：<0 空转、>0 拖滞；刹车可锁死（ω→0、slip→1）；摩擦上限 `μ×Fn`，冰面 / 沼泽真的会打滑 |
| 车轮绘制 | 由 `wheelRot` 真实轮角速度积分（`× DT`） | **与路面严格同步**：纯滚动时每帧转角 = `v/R·DT`；实测 `ω/(v/R)` 在滑行 0.99~1.05、猛加速 1.21~1.34 —— 后者就是真实的空转打滑，一并画出来（旧实现乘 0.06 系数抹平，既不贴路也看不见打滑）。单帧转角接近辐条周期时会频闪（6 辐条 60°），故按转角淡出辐条并补一道模糊环 |
| 悬挂 | 弹簧-阻尼（前后独立） | 压缩行程由真实冲量驱动，`squash` 由行程均值派生（不再有独立弹簧）；减震升级 +2% 刚度 / +3% 阻尼 / +0.08px 行程 |
| 阻力 | 空气 ∝ v²（`AIR_DRAG_K`）+ 滚动 ∝ Fn（`ROLL_RES_K`） | **极速由阻力自然平衡**（实测收敛在 ≈1.07×`MAXV`），只剩一道异常兜底 `NUM_CAP_V` 且全程测试 0 次触发 |
| 空中姿态 | 玩家角冲量 + 松键角速度保持 | 角动量守恒（轻车翻得快：竞速车 / 越野车实翻 23.1 vs 5.6 rad）；骑手头部为不等式约束，不是镜像补丁 |

**与旧模型的差异**（旧实现的"补丁"已全部删除，由静态断言守护）：

| 旧做法 | 现做法 |
|---|---|
| `LAUNCH_K / LAUNCH_MAX` 曲率起飞助推 | 删除：腾空完全由单侧接触 + 抛物线决定 |
| `VSPD_CAP` 硬夹垂直速度 | 删除：改由接触求解与阻力自然收敛 |
| `DOWNHILL_K` 下坡速度加成 | 删除：重力沿坡分量自己会加速 |
| `AIR_HEAD_DAMP` + `enforceHeadSide` 镜像补丁 | 删除：角冲量守恒 + `projHeadSide` 不等式约束 |
| 独立"画面弹簧" `squashK` | 删除：`squash` 从真实悬挂行程派生 |
| 速度上限夹断 | 删除：仅保留 `NUM_CAP_V=6000px/s` 的数值兜底（正常游玩与全部测试均不触发） |

**位置修正有上限**（`BIAS_MAX_V=400px/s`）：Baumgarte 修正速度 ∝ 侵入深度，若不设上限，
掉进深坑时一个子步内会注入上千 px/s；设上限后正常行驶（侵入 ≤ 数 px）完全不受影响。

**关卡地图**取代了原来的“12 张支线卡片墙 → 展开该支线 6 关”两层结构：主页面进入时**直接展开当前前沿支线**并在卡片上标「▶ 继续 第 N 关」，玩家不必在 12 张同构卡片里逐张扫读。12 条支线仍一次铺开（每张只渲染自己 6 关的摘要，不平铺 72 关），当前关卡下标写入存档，刷新后 HUD 与排位赛面板不再谎报「第 1 关」。

**游戏内 HUD** 为 Canvas 绘制：左上为**无底板的紧凑信息栏**（关卡名 + 变体徽标 + 里程进度条 + 限时门倒计时 + 姿态平衡，用文字投影保证在任何天空/地表上可读）、其下为无底板的燃料条（带刻度、低量脉冲），右下为弧形车速仪表（区间着色），底部为按键指示；机制警告（危险段超速 / 限时门紧张）为高优先级且不遮挡车身与前方赛道。所有元素位置由 `hudLayout()` 纯函数决定，三种视口下互不重叠且不被裁切。

**画质档位**（菜单 → 💾 存档 → 画面设置，或游戏内 ⚙️ 设置）：`高 / 中 / 低`，低档关闭全部全屏后处理（最快）。**缺省是「高」**——画质是玩家对画面的第一印象，不该一开场就发平；仅在低并发核数 / 窄屏设备上降为「中」。设置保存在 `dale_quality`（非存档键）。

**渲染倍率**（同一处的「画面锐度」，游戏内 ⚙️ 设置也有）：`省电 0.75× / 标准 1× / 锐利 1.25×`，缺省 `1×`。它与画质档是**正交的两个旋钮**：画质管"画多少东西"（阴影 / 雾 / 辉光 / 粒子），倍率管"画在多少像素上"（0.75× 只有 56% 像素，1.25× 有 156% 像素），所以"低画质但依然锐利"和"高画质但跑得动"都能单独达成。最终光栅化比例 = `DPR × 倍率`，绘制坐标始终是 CSS px，**渲染层代码对此无感**。设置保存在 `dale_scale`（非存档键）。

**可访问性**：全部可交互元素有 `:focus-visible` 焦点环、`role="button"` + `aria-label`；正文文本对比度 12 组合全部 ≥ 4.5:1、大字号 ≥ 3:1；四档断点（≥1024 / 768~1023 / ≤767 / 横屏高<480）；触摸目标 ≥ 44×44px。

## 🧪 自动测试

测试分**两个套件**，共用同一套打桩装置（`tools/harness.mjs`：DOM / Canvas / localStorage 打桩后
加载**真实游戏代码**，不是模拟）。两者分工是刻意设计的——同一批数据，一个**聚合成少量断言**，
一个**逐项摊开成海量细断言**：

| 套件 | 条数（实测） | 耗时 | 断言粒度 | 失败时能定位到 |
|---|---|---|---|---|
| `tools/autotest.mjs` | **476** | ~10s | **聚合**：一次跑完整场景，只断言"整体结论" | "约束求解器不收敛""坡顶腾空不成立"这类**子系统级**问题 |
| `tools/audit.mjs` | **5736** | ~0.5s | **逐项**：每关 / 每场景 / 每车 / 每变体 / 每个令牌**各查一遍** | **第几关的哪一项**（如 `L37 每层波长 ≥340px`、`T5 火山 traction`） |

要点：`autotest` 慢但条数少，适合验证**物理不变式与玩法闭环**（要真跑 72 关试跑、跑物理）；
`audit` 条数多一个数量级但飞快（纯数据遍历，无长程仿真），适合**回归定位**——失败信息直接指出
是哪一关、哪一项、期望多少、实际多少。日常改地形 / 改数值时，`audit` 是主力。

`tools/test-all.mjs` 是纯汇总器（自己不做任何断言）：逐个用 `child_process.execFileSync` 起子进程，
以**当前解释器**（`process.execPath`，用 node 跑就是 node、用 bun 跑就是 bun）执行，解析每个套件
自己打的汇总行，最后打印一张总表并给出总退出码（全绿 = 0，任一失败 = 1）。它会：

- 自动发现 `tools/audit-*.mjs` 体检模块并**各起一个独立进程**跑（模块不存在时静默跳过，不崩）
- 排除 `tools/audit-ctx.mjs`（它是共享上下文：加载全部模块并暴露 `ctx.check` / `ctx.section`，
  每个 `audit-<域>.mjs` 导出 `export default async function (ctx)`，本身不是一个测试模块）
- **以汇总行为准计数**，不靠数行：`autotest` 的输出里混有逐关用时表等缩进报告行，
  `audit` 的 detail 文案里本身含 ✅/❌ 字符，数行都会算错
- 计数/退出码对**崩溃**同样敏感：崩在 `finish()` 之前会被记为"崩溃"而不是"通过"

### 🧬 变异测试：验证"测试真的会红"

绿灯本身不能证明测试有效——全绿的套件和恒返回 `true` 的套件在输出上无法区分。
`tools/mutate.mjs` 故意往源码里注入 **13 类缺陷**，每注入一类就跑一遍
`audit.mjs`，看它会不会变红，然后**自动还原**源码：

```bash
bun tools/mutate.mjs            # 全部 13 类
bun tools/mutate.mjs 波长        # 只跑名字里含"波长"的那一类
```

| 结论 | 数据 |
|---|---|
| 13 类缺陷 | **抓到 10 · 假绿 2 · 跳过 1** |
| 抓到（真能红） | 令牌 CSS/JS 不同步、第 51 关长度突变、`game/` 反向 import `ui/`、`physics/` 反向 import `render/`（加载即崩）、坡度曲线改非单调（红 91 项）、`index.html` 内联 `onclick`、`main.css` 字面色值、摔车惩罚被放宽、地形换硬切破坏 C¹ 连续（红 145 项）、`NUM_CAP_V` 量级被改 |
| 假绿（真盲区） | 波长压到 150px、起跳唇压窄到 120px——两者的锚点值都被**稳定性下限**兜住了（`Math.max(MIN_WAVELEN, …)` / `Math.max(MIN_FEAT_W, …)`，见 `levels.js`），所以改**基准值**并不产生真实缺陷。护栏本身是对的，但"改坏一个已被兜住的常量"这件事测不出来 |
| 跳过 | 局部地貌振幅失控（深坑吞车）——锚点 `FEAT_AMP_MAX = 18` 在标定后已不是当前值（现为 `0`），变异没生效 |

即：**模块红线（反向依赖）、令牌双端一致性、地形 C¹ 连续性与曲率、难度单调性、机制常量**
这几类都有真实防护；**局部地貌振幅**这一类目前是假绿——这也是地形章节里 `FEAT_AMP_MAX = 0`
这件事必须写进文档、而不是藏进注释的原因。

## 🎯 开发须知（标度纪律）

所有速度/距离换算集中在 `src/config/constants.js`：

| 量 | 约定 |
|---|---|
| 世界标度 | **100 px = 1 m** |
| 车速 | `px/s`，`toKmh()` 换算显示 |
| 物理步长 | 固定 `DT = 1/60 s`，每步 6 个子步；子步位移 × `SUBV` = 真实 px/s |
| 极速 | 平路 `MAXV`，下坡允许到 `1.35 × MAXV` |

> 历史教训：早期版本做过一次"速度标度重构"但只改了物理，渲染/AI/特技/粒子里残留了 6~7 处
> 旧常数（`*SUB`、`260*SUB`、`MAXV/SUB`…），造成"代码在、功能死"的假功能。
> 因此现在**任何阈值都必须写成真实 px/s**，禁止裸换算。

## 💾 存档

使用 `localStorage`（键名前缀 `bike_`，共 13 个键）：金币、每辆车独立的升级等级、解锁关卡、星级、
车辆、静音、无限模式最佳成绩、成就，以及进度阶梯（`bike_prog`）、段位分（`bike_rating`）、
累计统计（`bike_stat`：总局数 / 总里程 / 总时长 / 最后游玩时间）。

**自动保存时机**：通关结算、解锁关卡/场景、购车、升级、成就、段位变化立即写盘；骑行中每 30 秒兜底写盘；
切到后台（`visibilitychange`）时写盘。**清空浏览器数据会重置存档**。

画面设置保存在两个非 `bike_` 前缀的本地设置键里，都**不是存档键**（导出存档不包含它们，清档也不会重置）：**`dale_quality`**（画质 高/中/低）与 **`dale_scale`**（锐度 0.75/1/1.25）。

**导入 / 导出**（菜单 → 💾 存档）：

- **导出**：把全部 `bike_` 键打包为
  `{ app: "dale-bike", format, savedAt, data }`，下载为 `dale-bike-save-<YYYYMMDD-HHmm>.json`
- **导入**：选择文件 → 完整校验（`app` / `format` / `data` 合法性）→ 展示"当前 vs 导入"对比
  （通关数 / 总星数 / 段位分 / 金币）→ 二次确认 → 整体覆盖后刷新界面。校验失败**不写入任何键**
- **重置**：二次确认后清空全部 `bike_` 键，回到"仅支线 1 第 1 关解锁"的初始状态

老存档（20 关结构）会在首次加载时自动迁移到 72 关结构（星级按全局索引映射、解锁不回退、星级数组补齐），
迁移由 `bike_v` 版本号守护，只执行一次。
