# 🚲 自行车越野 · 真实物理版

原生 JavaScript + Canvas 实现的物理越野自行车游戏，**零依赖、零构建**，打开网页即玩。

- 没有跳跃键：靠坡度冲起腾空，空中用 `←/→` 调整车身姿态落地
- 三质点刚体物理：油门翘头 / 刹车栽头 / 坡顶腾空 / 落地缓冲 / 陡坡打滑都是"算出来"的
- 12 个场景 / 12 条支线 × 6 关 = **72 关 + 最终任务**，6 种关卡变体，4 类机制性难度
- 比赛模式、排位赛（普通 / 高级）、无限模式（登顶后可自选场景）
- 金币、升级车间、车库、成就、打赏、移动端触摸操作、浏览器本地存档（可导出 / 导入）
- 视觉体系：设计令牌双端一致（CSS ⇄ Canvas）+ 玻璃拟态组件库 + 四档画质（高/中/低/关）+ 可访问性与响应式

## 🗺 内容与玩法

**场景（12）**：绿野、雪原、荒漠、月面、雨林、火山、冰川、红岩峡谷、沼泽、城市废墟、天空浮岛、极夜星空。
每个场景有各自的重力、抓地、天空/地表配色、装饰与环境特效（数据驱动，渲染层无 `theme === 数字` 硬编码）。

**关卡**：12 条支线 × 6 关 = 72 关，另加 1 关「最终任务」（超长赛道、多场景分段串联）。
支线内链式解锁、支线间可并行推进；难度（坡度 / 落差 / 颠簸 / 机制密度 / 三星时限）沿全局进度单调递增。
72 关全通后解锁「最终任务」，通关最终任务 → 收到比赛邀请 → 解锁排位赛。

**关卡变体（6）**：每条支线的第 3、5 关是特殊变体，其余为常规关。

| 变体 | 内容 |
|---|---|
| `normal` | 标准赛道 |
| `sprint` | 限时冲刺：门限极严、赛道无补给 |
| `gauntlet` | 障碍迷宫：障碍成簇密布，必须减速穿越 |
| `airtime` | 空翻挑战：需累计滞空 + 连招达标才算通关 |
| `fuelrun` | 燃料极限：赛道仅 1 个油罐，必须规划 |
| `downhill` | 极速下坡：危险段密集，须精准刹车 |

**机制性难度**：

- **障碍物**：高速撞上必摔车，可减速碾过或腾空飞越；不生成在出生点/终点缓冲区
- **危险段**：车身中点超速进入必摔车，有可提前预判的限速路标；低于阈值可安全通过
- **限时门**：每关 3~5 道，累计时限比三星放宽 20%；任一门超时本局判负，且不写入星级与解锁
- **摔车惩罚**：每次摔车扣 8% 燃料 + 2 秒计时惩罚（计入三星判定用时）

**玩法模式**：

- **闯关**：左 上角为支线任务面板，逐支线选关
- **比赛**：与 AI 对手在同一赛道竞速，先到终点者胜（胜 +300 金币）
- **排位赛**：普通 / 高级两档；胜负改变段位分（不低于 0），段位分 ≥ 1200 解锁高级赛，≥ 2400 视为登顶
- **无限模式**：未登顶为随机地形；登顶后可自选已通关场景（重力 / 抓地 / 地表 / 环境特效随之切换）

## 🚀 运行

本项目使用 **原生 ES Module**，浏览器出于安全策略**不允许**用 `file://` 直接打开模块（会报 CORS 错误），
所以本地运行需要一个静态服务器（任选其一）：

```bash
# 方式 1：Python（推荐，随系统自带）
python -m http.server 8000
# 然后浏览器打开 http://127.0.0.1:8000/

# 方式 2：Node
npx serve .
```

## 🏁 比赛模式的 AI 配速

AI 巡航速度按**本关三星要求均速 `den3`** 标定（而不是玩家极速 `MAXV`）——因为 `MAXV` 由车辆/升级决定，
不随关卡变难而提高；早期实现用 `MAXV×(1+42%×ramp)` 会让后期 AI 达到三星节奏的 2~3 倍，比赛几乎必输。

| 模式 | AI 配速（相对 `den3`） | 追赶修正 |
|---|---|---|
| 普通比赛 | `0.68×` | 有（`[0.80, 1.25]×`，AI 领先降速 / 落后提速） |
| 普通排位赛 | `0.70× → 0.90×`（随段位分） | 无（纯配速检验） |
| 高级排位赛 | `0.95× → 1.25×`（随段位分） | 无 |

普通比赛的配速上限为 `0.68 × 1.25 = 0.85 × den3 < 1`，因此**只要跑出三星水平就必定赢**；追赶修正保证对手
不会一路绝尘，也不会因一次小失误就被拉开。

## 🎨 视觉体系（第 2 期）

界面由“**令牌 → 组件 → 动效 → 后处理**”四层构成，零依赖、零构建：

| 层 | 位置 | 说明 |
|---|---|---|
| 设计令牌 | `styles/tokens.css` + `src/config/ui-tokens.js` | 唯一事实来源，**两端逐键等价**（142 项），由断言守护；表面层级 4 档 / 玻璃层 / 强调色 / 语义色 / 文本 3 档 / 排版 / 间距 / 圆角 / 动效 |
| 组件层 | `styles/main.css` + `src/ui/components.js` | `glass-sheet` / `card` / `chip` / `btn(primary\|ghost\|danger)(sm\|lg)` / `progress` / `stat` / `tabs` / `badge` / `empty`，每个组件覆盖 hover / active / focus-visible / disabled / aria-disabled 五态；纯函数渲染 HTML，**不允许内联配色** |
| 动效与反馈 | `styles/main.css` + `src/core/toast.js` + `src/ui/menu.js` | 面板进出场过渡、Toast 四型分级（同屏上限 2 条排队）、结算结果卡（星级逐颗点亮 / 金币滚动 / 段位 Δ / 下一关与返回菜单）；`prefers-reduced-motion` 下全部降级为无位移瞬时 |
| 画面后处理 | `src/render/postfx.js` | 渐晕、按场景主题的暖冷色彩分级、速度拖影、远景淡化、`THEMES[i].ambient` 天气覆盖（雪/沙/雨/灰烬/雾/花粉）；复用离屏画布，无逐帧对象分配；**不改变物理** |

**主菜单**改为三组信息架构：主玩法（闯关 / 比赛模式 / 最终任务 / 排位赛 / 无限模式）、养成与进度（车库 / 升级车间 / 成就 / 存档）、支持；顶部 Hero 区展示状态摘要（车辆 / 金币 / 通关进度 / 总星 / 段位 / 无限最佳），锁定的入口直接写明解锁条件与当前进度。支持方向键 + Enter + Esc 纯键盘操作，菜单背景为活体（场景渲染叠加渐晕与流动光斑）。

**支线任务面板**为“12 张支线卡片墙 → 展开该支线 6 关”的分层结构（主题色描边 + 场景缩略示意 + 完成度 + 总星），不再一次性平铺 72 关。

**游戏内 HUD** 改为 Canvas 玻璃仪表盘：左上分层信息卡（关卡名 + 变体徽标 + 里程进度条 + 限时门倒计时 + 姿态平衡）、带刻度的燃料量表（低量脉冲）、弧形车速仪表（区间着色）、底部按键指示；机制警告（危险段超速 / 限时门紧张）为高优先级且不遮挡车身与前方赛道。所有元素位置由 `hudLayout()` 纯函数决定，三种视口下互不重叠且不被裁切。

**画质档位**（菜单 → 💾 存档 → 画面设置）：`高 / 中 / 低 / 关`，低档关闭拖影与天气流动，移动端 / 低 DPR 默认中档；设置保存在 `dale_quality`（非存档键）。

**可访问性**：全部可交互元素有 `:focus-visible` 焦点环、`role="button"` + `aria-label`；正文文本对比度 12 组合全部 ≥ 4.5:1、大字号 ≥ 3:1；四档断点（≥1024 / 768~1023 / ≤767 / 横屏高<480）；触摸目标 ≥ 44×44px。

## 🎯 开发须知（标度纪律）

所有速度/距离换算集中在 `src/config/constants.js`：

| 量 | 约定 |
|---|---|
| 世界标度 | **100 px = 1 m** |
| 车速 | `px/s`，`toKmh()` 换算显示 |
| 物理步长 | 固定 `DT = 1/60 s`，每步 6 个子步；子步位移 × `SUBV` = 真实 px/s |
| 极速 | 平路 `MAXV`，下坡允许到 `1.35 × MAXV` |

> 历史教训：早期版本做过一次"速度标度重构"但只改了物理，渲染/AI/特技/粒子里残留了 6~7 处
> 旧常数（`*SUB`、`260*SUB`、`MAXV/SUB`…），造成"代码在、功能死"的假功能。
> 因此现在**任何阈值都必须写成真实 px/s**，禁止裸换算。

## 💾 存档

使用 `localStorage`（键名前缀 `bike_`，共 13 个键）：金币、每辆车独立的升级等级、解锁关卡、星级、
车辆、静音、无限模式最佳成绩、成就，以及进度阶梯（`bike_prog`）、段位分（`bike_rating`）、
累计统计（`bike_stat`：总局数 / 总里程 / 总时长 / 最后游玩时间）。

**自动保存时机**：通关结算、解锁关卡/场景、购车、升级、成就、段位变化立即写盘；骑行中每 30 秒兜底写盘；
切到后台（`visibilitychange`）时写盘。**清空浏览器数据会重置存档**。

画面设置（画质 高/中/低/关）保存在 **`dale_quality`** —— 这是非 `bike_` 前缀的本地设置键，**不是存档键**，导出存档不包含它，清档也不会重置画质。

**导入 / 导出**（菜单 → 💾 存档）：

- **导出**：把全部 `bike_` 键打包为
  `{ app: "dale-bike", format, savedAt, data }`，下载为 `dale-bike-save-<YYYYMMDD-HHmm>.json`
- **导入**：选择文件 → 完整校验（`app` / `format` / `data` 合法性）→ 展示"当前 vs 导入"对比
  （通关数 / 总星数 / 段位分 / 金币）→ 二次确认 → 整体覆盖后刷新界面。校验失败**不写入任何键**
- **重置**：二次确认后清空全部 `bike_` 键，回到"仅支线 1 第 1 关解锁"的初始状态

迁移由 `bike_v` 版本号守护，只执行一次。
